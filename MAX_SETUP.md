# Публикация в MAX — подробная инструкция

Тот же автоматический конвейер, что и для Telegram: approved JSON → проверка → фирменная карточка 1080×1350 → публикация по расписанию без подтверждения. Telegram при этом не меняется: у MAX свой publisher, свой workflow и свой state.

## Как устроено

```text
content/approved/YYYY-MM-DD.json (ручной или сгенерированный)
  → scripts/validate_content.py
  → dbp-design build (карточки PNG + manifest.json)
  → scripts/publish_max.py
      → POST /uploads?type=image        (загрузка картинки в MAX)
      → POST /messages?chat_id=...      (пост с картинкой и текстом)
  → state/max/<hash>.json               (анти-дубль: повтор не отправится)
  → content/published/YYYY-MM-DD_slot.json (архив, общий с Telegram)
```

Текст берётся из поля `max_text` (генератор ставит его равным `telegram_text`, редактор может развести). Подпись «Не переплачивай» добавляется централизованно publisher-ом и в JSON не хранится.

## Шаг 0. Требования

- Верифицированный профиль организации, ИП или самозанятого (резидент РФ) на платформе MAX для партнёров. Без него создать бота нельзя.
- Канал в MAX, куда будут выходить посты.
- Бот добавлен в этот канал **как администратор** — без этого MAX не пришлёт событие добавления и не даст публиковать.

## Шаг 1. Создать бота и получить токен

1. Откройте https://business.max.ru/self и войдите.
2. Раздел **Чат-боты** → создать бота: название, описание, логотип (подойдёт `channel-avatar.png`), контакты.
3. Отправьте бота на модерацию. Токен появляется только после успешной модерации (обычно до 48 часов в рабочие дни).
4. Скопируйте токен: **Чат-боты** → нужный бот → **⋮** → **Настройки** → значок копирования справа от поля с токеном. Альтернатива — мини-приложение «MAX для бизнеса» → команда **Получить токен**.
5. Токен никуда не вставляйте в файлы репозитория — только в Secrets (шаг 4).

## Шаг 2. Добавить бота в канал как администратора

В MAX откройте свой канал → настройки канала → добавить администратора → найдите бота по имени → выдайте права на публикацию постов. Бот должен быть именно администратором: только тогда API присылает события о канале и разрешает отправку постов.

## Шаг 3. Добавить файлы в репозиторий

В репозитории `andrey9653246431-spec/money` через **Add file** добавьте файлы, сохраняя пути:

```text
scripts/publish_max.py
scripts/discover_max_chat.py
.github/workflows/publish-max.yml
.github/workflows/discover-max-chat.yml
tests/test_max_pipeline.py
state/max/.gitkeep
MAX_SETUP.md
```

Сделайте commit в `main`. Существующий `.github/workflows/publish.yml` (Telegram) трогать не нужно.

## Шаг 4. Secrets и Variables

Откройте **Settings → Secrets and variables → Actions**:

Secrets (значения не видны после сохранения):

```text
MAX_BOT_TOKEN   — токен бота из шага 1
MAX_CHAT_ID     — id канала MAX (получите на шаге 5)
```

Variables:

```text
MAX_PUBLISHING_ENABLED = false   (сначала выключено)
MAX_CHANNEL_URL        = https://max.ru/...  (необязательно: ссылка на канал, добавляется в подпись под постом)
```

## Шаг 5. Узнать chat_id канала

Важно: API MAX **не даёт список чатов** (метод `GET /chats` отключён с июня 2026). `chat_id` канала приходит только в событиях `bot_added` / `bot_started`. Поэтому нужен разовый поиск через Long Polling.

1. Убедитесь, что у бота **нет активной Webhook-подписки** (`POST /subscriptions`): пока активна подписка, Long Polling не работает. Если подписку создавали — удалите её (`DELETE /subscriptions`).
2. Откройте **Actions → Discover MAX channel chat_id → Run workflow** (`wait_seconds` — 180).
3. Пока workflow ждёт, добавьте бота в канал как администратора. Если бот уже был в канале до запуска, событие могло пройти раньше: тогда удалите бота из канала и добавьте снова во время ожидания.
4. В логах появится строка вида:

```text
FOUND: chat_id=-12345678901234; type=bot_added; kind=канал
MAX_CHAT_ID=-12345678901234
```

5. Вставьте это число (со знаком минус) в Secret `MAX_CHAT_ID`.

Локальная альтернатива (если запускаете скрипты на своём компьютере):

```bash
MAX_BOT_TOKEN=ваш_токен python scripts/discover_max_chat.py
```

## Шаг 6. Проверка без отправки (dry-run)

Откройте **Actions → Publish approved MAX content → Run workflow**:

```text
slot: morning
content_date: 2026-11-15   (любая дата с JSON или будущая — сгенерируется)
dry_run: true
```

В логах должны появиться `GENERATED` (если JSON не было), `OK`, `Render cards` и `DRY RUN`. MAX API не вызывается, state не меняется. Для dry-run токен и chat_id не нужны.

## Шаг 7. Тестовая отправка

1. Временно укажите в `MAX_CHAT_ID` id **тестового** канала (получите его тем же workflow Discover).
2. Запустите **Publish approved MAX content** с `dry_run: false`.
3. Проверьте в тестовом канале: пост с фирменной картинкой, полный текст, подпись «Не переплачивай» в конце.
4. Запустите тот же workflow ещё раз — в логах должен быть `SKIP` (анти-дубль сработал).
5. Замените `MAX_CHAT_ID` на боевой канал.

## Шаг 8. Включить расписание

В Variables установите `MAX_PUBLISHING_ENABLED=true`.

Расписание по Москве — **09:08, 13:08, 20:08** (на 5 минут позже Telegram, чтобы два workflow не гонялись за генерацией одного JSON). Утренний запуск создаёт JSON дня, если его нет; дневной и вечерний используют тот же файл. По воскресеньям вечером вместо обычного поста выходит гороскоп — как и в Telegram.

## Особенности MAX, которые учтены в коде

- Домен API — только `https://platform-api2.max.ru` (старый `platform-api.max.ru` не использовать).
- Токен передаётся только в заголовке `Authorization`, не в URL.
- **Сертификат Минцифры (Russian Trusted CA).** API MAX работает на сертификатах НУЦ Минцифры. Workflows сами скачивают корневой и выпускающий сертификаты с Госуслуг и устанавливают их перед запуском (шаг *Install Russian Trusted CA for MAX API*). Если запускаете скрипты локально и видите `CERTIFICATE_VERIFY_FAILED` — скачайте сертификаты на https://www.gosuslugi.ru/crt и добавьте в доверенное хранилище.
- Текст поста — до 4000 символов: наши посты (до ~1200) уходят одним сообщением с картинкой. Более длинный текст publisher режет на части.
- Не более 2 сообщений в секунду в один канал: publisher делает паузы между частями.
- Картинка: до 50 МБ и не более 7680×7680 px — карточки 1080×1350 подходят с запасом.
- Для каналов уведомления (`notify`) отключить нельзя — publisher всегда отправляет с `notify=true`.
- `chat_id` канала — отрицательное число. В Secret вставляйте как есть, со знаком минус.

## Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| `CERTIFICATE_VERIFY_FAILED` | Нет сертификата Минцифры | В workflow шаг уже есть; локально — установить Russian Trusted CA с https://www.gosuslugi.ru/crt |
| `MAX ... 401` | Неверный токен | Проверьте Secret `MAX_BOT_TOKEN` |
| `MAX ... chat.denied` (403) | Бот не администратор канала или удалён из него | Добавьте бота обратно как администратора |
| `attachment.not.ready` | Картинка ещё обрабатывается на сервере MAX | Publisher сам повторяет с паузой; если запуск упал — просто запустите снова |
| Событие `bot_added` не пришло | Бот добавлен до запуска / активна Webhook-подписка | Переустановите бота в канал во время ожидания; удалите подписку |
| В логах `SKIP` | Пост уже опубликован (state) | Это нормально, дубль не отправится |
| Расписание не публикует | `MAX_PUBLISHING_ENABLED` не равен `true` | Установите `true` в Variables |
| Дубли в канале | State не закоммитился (push отклонён) | Проверьте ветку `main`: Actions должны иметь право записи |

## Чек-лист после установки

- [ ] Бот создан, модерация пройдена, токен в Secrets
- [ ] Бот — администратор канала MAX
- [ ] `chat_id` получен через Discover и записан в Secrets
- [ ] Dry-run завершился строками `DRY RUN`
- [ ] Тестовая отправка в тестовый канал успешна, повтор — `SKIP`
- [ ] `MAX_PUBLISHING_ENABLED=true`
- [ ] Первый scheduled run: в Actions есть artifact `max-...`, в канале — пост с картинкой
